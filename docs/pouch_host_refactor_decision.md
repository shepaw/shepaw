# 储物袋宿主重构（决策记录）

- 日期：2026-09-29
- 状态：**已裁定，落地中**（2026-09-29 起：身份锚到袋子、Agent 名册）
- 关联：`docs/storage_space_plan.md`、`docs/storage_protocol_spec.md`、`docs/CLIENT_PROFILES.md`

## 1. 问题

惜宝的回合、群编排、定时任务和事件感知跑在打开会话的那台 App 里。手机一息屏，进程被挂起，任务中断。

同时 App 又是唯一连得上每一台 Hub 的一端：群成员可以来自多台设备，编排器按 `source_peer_id` 分别拨号。把惜宝单独搬到某一台 Hub 上，那台机器看不见其他 Hub，多设备同群就不成立。

## 2. 裁定

一份储物袋就是一个身份。主机只是当前把这份身份跑起来的机器，可以更换。手机应用和电脑应用都是这台主机 Hub 的客户端。

```
手机应用 ──┐
           ├── 客户端（显示、操作、本机能力）
电脑应用 ──┘
           │
           ▼
     主机上的 Hub
     身份 = 储物袋的密钥
     惜宝、群编排、定时任务、配对名单、全部核心数据
           │
           ├── 工人 Hub（另一台机器上的 Codex / Claude 等）
           └── 储物袋就在这台主机的磁盘上
```

Channel 继续只做密文收件箱和 NAT 隧道，不跑编排，不存放明文。

### 2.1 应用登录一只袋子（2026-09-30）

App 不持有主机逻辑。手机和电脑都先连一台 agent-hub，再从这台机器上的袋子里选一个登录。一台机器可以放多个袋子，一个袋子一个身份，密钥留在那只袋子里。没登录之前不进主页，也不在 App 里把回合跑起来。App 和 Hub 在同一台电脑上时，同样要先选袋子。

袋子目录在 Hub 家目录下的 `pouches/<id>/`。App 自己只记下当前登录的是哪一只、连的是哪台 Hub。

## 3. 身份

现在没有账号。`device_id` 是本机 Noise 公钥的哈希，身份落在宿主机器上。换机器又不带上这份密钥，就变成另一台设备，配对和 `pouch://` 路径都要重来。

重构后：

- **账号 = 储物袋的密钥。** 一个袋子一个身份，不另做邮箱或登录服务器。
- 惜宝、聊天、群、编排状态、配对名单、Agent 名册都挂在这个身份上。
- 应用连上哪份袋子，会话和惜宝就是那一份。应用记下的是袋子的指纹；端点变了，重新连上同一个身份。
- 应用自己、工人 Hub 仍各有密钥。袋子的白名单用这些密钥区分「我的手机 / 我的电脑 / 那台跑 Codex 的机器」，并把相机、定位、本机文件的调用送到对应设备。这些密钥标识接入方，不是账号。

主机身份从袋子恢复，不从系统钥匙串单独生成。密钥只留在钥匙串、不进袋子的话，新机器会变成另一台设备。现有 `DeviceIdentity.exportIdentity` / `importIdentity`（快照里的 `identity.enc`）就是这条路径，要变成启动时的权威来源。

## 4. 角色

| 角色 | 做什么 | 不做什么 |
|---|---|---|
| 主机 Hub | 惜宝回合、群编排、定时任务、事件感知、设备名单、储物袋权威 | 不代替工人 Hub 跑它们的 agent |
| 手机 / 电脑应用 | 显示与操作；本机才有的能力（相机、定位、该设备上的文件）经客户端 CLI 提供 | 不持有惜宝，不持有第二份核心数据，不跑群编排 |
| 工人 Hub | 跑本机引擎（Codex、Claude 等）；把要交出来的产物写入主机这份袋子 | 不把本机工作目录并进储物袋；彼此不直接编排 |
| Channel | 投递密文、打隧道 | 不跑编排、不存文件明文、不是身份 |

电脑应用走现有的本机加入（`LocalAgentHubService`）配上这台 Hub。手机扫一次这台 Hub 的二维码配上同一台，外网走 Channel 隧道。配完之后两边都只留这一条连接。

惜宝的工具循环在主机 Hub 上自建（把现在的本地 LLM 循环抬到 Hub）。第三方引擎留在工人 Hub，由惜宝派活，不把惜宝塞进它们的 harness。

## 5. 储物袋

用户自己的手机和电脑不再各持一份袋子再做镜像。连上这台 Hub，就读写它磁盘上的那一份。会话、惜宝的记忆、群里的产物都在这里。底下仍然写在这台主机的设备目录里，对用户只呈现一份。

- 登记在这台主机下的，是用户自己的设备，共享整袋。
- 工人 Hub 只把要交出来的产物写进这袋。
- 权威只有这一份。备份和导出也在这台机器上。

### 5.1 核心数据进袋子

换主机时拷走这一份储物袋（含身份密钥），新机器导入后继续当同一台主机。手机和电脑应用不用迁。

这句话要成立，权威必须就在袋子里。现状（`docs/CLIENT_PROFILES.md`）是双层：

| 数据 | 现在的权威 | 重构后 |
|---|---|---|
| 灵魂、结构化记忆 | `cognition/`；另有 `she_profile.db` / `she_memory.db` / `minds.db` | `cognition/` 不变。这三份库改到 `pouch://app/shepaw/sqlite/` |
| 聊天消息、搜索 | App SQLite `messages` | `pouch://app/shepaw/sqlite/shepaw.db` |
| 群、编排游标、定时任务、配对名单 | App SQLite | 同一份库；工具输出在 `pouch://app/shepaw/sqlite/tool_results.db` |
| 主机身份 | 系统钥匙串；快照里另有 `identity.enc` | 以袋子里的身份记录为准，启动时导入 |

`runtime/` 下的 `soul.md` / `memory.md` 仍是人读镜像，不回灌 `cognition/`。

### 5.2 Agent 名册

接入的 Agent 记在袋子里的一张名册上。每张卡拆成两截。

**展示（永久保留）**  
第一次接入时写定，之后只更新、不删除：袋子内稳定 id、名字、头像、引擎、来自哪台工人 Hub。消息上继续带发送者 id 和写入时的名字；头像和引擎从这张卡读。卡还在，卸掉设备之后旧消息仍能画出来。后来改名只影响新消息。

**拨号（仅在接入期间）**  
工人 Hub 的指纹、它在那台 Hub 上的 id、是否在跑、工作区地址。群编排、派发、级联只查这一截还在的卡。惜宝没有这一截，她的卡绑在袋子自己的身份上。

卸掉一台设备时，只清掉它名下那些卡的拨号信息。同一台 Hub 上的同一个 Agent 再连上来，用「工人 Hub 指纹 + 远端 id」对上原卡，把拨号信息填回去，不另开一张。群成员存这些卡的 id。

头像等二进制跟卡一起放在袋子里，换主机后历史还能显示。

## 6. 再扫一台设备

不是把手机已经配上的记录拷到主机。Noise 白名单认的是完成握手的那一方的公钥。

1. 手机或电脑应用扫到二维码，解析端点、配对码、指纹和公钥。配对码大约 5 分钟有效。
2. 应用上先给用户看指纹，确认了再往下走。
3. 应用把这份还没过期的配对信息交给主机 Hub，自己不发起握手。
4. Hub 用储物袋的密钥去连。外网优先走二维码里的 `channel` 端点。
5. 对方确认屏上出现的是这份储物袋的身份。接受后，配对记在 Hub 上，Agent 卡写入名册。
6. 两个应用刷新的都是 Hub 的设备列表。扫描的那台应用自己不留下配对记录。

Hub 仪表盘取码（只取票据、不配对）同样处理：应用可以帮着要码，`requestPairing` 仍由 Hub 完成。

已经配在手机上的旧设备不会自动出现。要迁的话，由手机介绍一次，请对方把储物袋的公钥加入白名单。

## 7. 和现状的差距

下面这些今天仍在「打开会话的那台 App」里，要改到主机 Hub：

- 惜宝固定 id `she-builtin-agent-001` 是本机行，`isReservedLocalAgentId` 禁止被 peer 覆盖。重构后手机和电脑上不再各养一条本地惜宝，应用里的惜宝是这份袋子的视图。
- `AgentMessagingService.sendMessageToAgent` 在 `agent.isLocal` 时走本机 LLM 循环。客户端改为把回合交给 Hub。
- `GroupOrchestrationService` 在发消息的那台 App 里拨每一台 Hub。改为只在主机 Hub 上跑，由它按名册的拨号信息去叫工人 Hub。主机 Hub 因此要同时是 host（接待两个应用）和 client（拨工人 Hub）。现在的 agent-bridge 只有 host 这一半。
- `ScheduledTaskService` 随 App 进后台暂停。时钟放在 Hub 上。
- `HubCliExecute` 把数据面 CLI 绑在发起 `agent.chat` 的 App 上。记忆、store、chat、agents、workflow 在 Hub 上执行；应用只注册设备类命令。群成员 CLI 白名单在新的执行点上保持同一套。
- 聊天权威在 SQLite。改为落在储物袋，随袋子迁移。

已经能沿用的：peer 断线后续传、审批回传、Channel 隧道、储物袋的设备目录和 `store.*` 帧。工人 Hub 上的回合仍在那台机器上跑完，主机 Hub 收回结果。

## 8. 明确不做

- 不把编排、惜宝或储物袋明文放进 Channel 进程。
- 不把工人 Hub 的工作目录并进这份袋子。
- 不做袋子之上的云端账号。一个袋子就是一个身份。
- 不在每个应用里保留一份可独立运行的惜宝。没有开着的宿主时，客户端只能看已经拉下来的界面，不能在本地把回合跑完。

## 9. 落地进度

已进代码的身份与名册：

- 启动时 `DeviceIdentity.ensureFromPouch`：袋子里有 `.system/pouch_identity.v1` 就导入钥匙串；没有就把当前密钥种进袋子。
- `AgentRosterStore`（`.system/agent_roster.json`）：展示信息永久保留，拨号在 `detachHub` 时清掉，同一工人 Hub 指纹 + 远端 id 再连对上原卡。惜宝用 `ensurePouchBound` 种一张没有拨号的卡。

`runtime/.../session.json` 仍是单向镜像，不回灌聊天。聊天权威是储物袋里的 `shepaw.db`。`.system/chat/` 的追加日志同样不是读的来源。

主机收到工人 Hub 的 `agent_list_resp` 后把 Agent 写进名册。同一指纹 + 远端 id 对上原卡；这次名单里没有的卡只清拨号。卸掉这台设备同样只清拨号。客户端不写这份名册。握手返回时还没有名单，所以不在那一刻写卡。

主机拨工人 Hub（群成员或单聊）之前先查这张卡。拨号还在，就按指纹找到已配对的那台再发。拨号已清，或对不上设备，就停下来，不再用旧的 peer id。名册里还没有这张卡时，仍走原来的 peer id。客户端不查这本名册。

主机同步工人 Hub 时，本机 agent 行的 id 用名册卡的 id。群成员存的就是这个 id。名单里不再出现、或设备卸掉之后，这行留下并标成离线，方便旧消息和群成员还能画出名字。惜宝的固定 id 不会被盖掉。

客户端不创建本机惜宝，也不跑定时任务和派发。主机上的时钟不随 App 进后台停，服务本身也会拒绝在主机上暂停、在客户端上启动。客户端执行 CLI 时只放行 `os` 和 `help`；记忆、store、chat、workflow 等数据面命令留在主机。自己的设备不用另开分享开关就能看到主机的惜宝，客户端把她落在 `she-builtin-agent-001` 上，回合发给主机，不在本地跑。已经有一条本机惜宝时不覆盖。客户端不能在本机改群，群的创建和成员变更留在主机。没有登录记录时 App 不是主机，回合不会在本机开跑。

客户端启动时不再把主机运行时拉起来：不检查工人健康、不开 ACP、不暴露本机 Agent、不恢复本机回合、不同步第二份袋子、不播 presence、不做记忆交换、不种技能和模型、不跑快照和目录绑定。连接、通知，以及本机的 `os` / `help` 仍在。

已接上的回合交接点（App 登录一只袋子之后，把回合交给那台 agent-hub）：

- `.system/pouch_role.json` 写成 `client` 并带上 `host_peer_id` 后，这台 App 不再本地跑群编排，也不再本地跑本机 LLM 回合。
- 群消息走 `pouch_group_turn`，本机 Agent 回合走 `pouch_dm_turn`。主机确认自己是 host 之后，调用现有的 `ChatService`，再用 `pouch_turn_event` 把流式块送回。需要用户确认时，主机发 `kind: interaction`，客户端用原来的确认回调问用户，再以 `pouch_interaction_resp` 把结果送回；本机工具确认走 `os_tool`。三十分钟没人答就按没确认继续。
- 应用库直接建在 `pouch://app/shepaw/sqlite/`：`shepaw.db`、`tool_results.db`、`she_profile.db`、`she_memory.db`、`minds.db`、`agent_traces.db`，以及 `agent_memory_*.db`。不从文稿目录或 `.system/sqlite/` 搬旧文件。界面读消息仍只走 `ChatService`：本机读这份库，客户端用 `pouch_chat_read` 向主机要同一页。`.system/chat/` 的追加日志还不是读的来源。
- 客户端回合可以带附件。先用 `pouch_file_begin` / `pouch_file_chunk` / `pouch_file_end` 把字节交给主机（单片 48KB，整文件不超过 20MB）。主机确认自己是 host 之后写入 `runtime/…/attachments/<sha256>`，再把同一份字节交给现有的 `ChatService`。单聊和群聊都在主机的消息库里留下附件气泡。这些帧和回合帧都要写进 `PeerConnection` 的控制帧名单，否则到不了另一端。
- 客户端扫码或粘贴配对链接时，先给用户看指纹。确认后把票据交给主机，自己不发起握手，也不把对方写进本机名单。主机用储物袋的密钥去连，外网优先走二维码里的 `channel` 端点。通讯录和会话列表读的是主机的设备名单。App 连上本机 agent-hub 时用自己的设备密钥配对，不把袋子的密钥装进 App。
